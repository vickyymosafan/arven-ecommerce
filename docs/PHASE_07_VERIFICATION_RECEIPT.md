### 4.3 Known Operational Note (`local_fs` Staging Upload vs. Presigned Object Storage PUT)

- **Observation (`SEC-P7-OBS-01`):** In local development (`STORAGE_DRIVER=local_fs`), `POST /api/v1/admin/products/:id/3d-assets/:assetId/upload-staging` accepts base64-encoded `.glb` payloads through the NestJS Express JSON body parser (`1 MB` default body limit, which accommodates procedural studio garment GLBs up to ~`700 KB`).
- **Staging / Production Operation:** In staging and production (`STORAGE_DRIVER=s3` / MinIO / Cloudflare R2), clients upload binary `.glb` payloads (`<= 15 MB`) **directly** to the presigned `PUT` URL returned by `POST /api/v1/admin/products/:id/3d-assets/presign` (bypassing the API JSON body parser), and then call `POST .../confirm` to enqueue asynchronous BullMQ `3d-assets` validation. If `local_fs` mode is ever used to test multi-megabyte raw `.glb` uploads locally, increase the route-scoped body parser limit on `upload-staging` to `22mb` while keeping the global API JSON limit at `1mb`.
